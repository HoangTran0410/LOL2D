# Minimap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fog-respecting minimap in the top-left that expands on a tap, and teleports the player on a tap of the expanded map.

**Architecture:** A `Minimap` class beside `Camera`/`FogOfWar`/`TerrainMap`, drawn on the canvas in screen space after the fog. Geometry and hit-testing stay out of `draw()` so they are testable with no canvas — the shape `TouchControls` already uses.

**Tech Stack:** TypeScript, p5.js global mode, Vitest (`environment: 'node'`), Playwright.

**Spec:** `docs/superpowers/specs/2026-08-15-minimap-design.md`

## Global Constraints

- **p5 global mode.** Only `draw()` and the buffer builder may touch p5 globals, and nothing at module eval time. Every other method must run in a plain node test.
- **Map is 6400×6400** (`Game.mapSize`).
- **Fog flag is `visibleToPlayerTeam`** (was `willDraw` when this plan was written) — `FogOfWar.calculateSight()` sets it each frame on `AttackableUnit`; do not compute visibility. It is a rendering answer only, never a targeting one.
- **Commit form:** `git add <new files>` then `git commit -m "..." -- <explicit paths>`. Never `-A`, never `.`, never bare. Trailer `Claude-Session: https://claude.ai/code/session_017chrooEFCy9rvuYkvD9mjh`.
- **Prettier** per `.prettierrc` in new files; never `--write` existing ones.
- **Known pre-existing failure, not yours:** `drive-touch-controls.mjs`'s "the stick walks the champion" (112-115 vs a `> 120` threshold).

### Task 1: The transform and hit-testing

**Files:** Create `src/game/gameObject/map/Minimap.ts`, `tests/game/map/Minimap.test.ts`

**Interfaces:** Produces `MinimapRect = { x: number; y: number; size: number }`, `worldToMinimap(world, rect, mapSize)`, `minimapToWorld(screen, rect, mapSize)`, `hitTest(point, rect)`, and `MINIMAP_SIZE` / `MINIMAP_MARGIN` / `EXPANDED_FRACTION`.

- [ ] **Step 1: Write the failing test**

```ts
import { describe, expect, it } from 'vitest';
import { hitTest, minimapToWorld, worldToMinimap } from '../../../src/game/gameObject/map/Minimap';

const MAP = 6400;
const rect = { x: 12, y: 12, size: 150 };

describe('minimap transform', () => {
  // A transform wrong by the same factor both ways round-trips perfectly, so
  // the round trip alone proves nothing. This pins one known absolute.
  it('world origin maps to the rect origin', () => {
    expect(worldToMinimap({ x: 0, y: 0 }, rect, MAP)).toEqual({ x: 12, y: 12 });
  });

  it('the far corner maps to the far corner', () => {
    expect(worldToMinimap({ x: MAP, y: MAP }, rect, MAP)).toEqual({ x: 162, y: 162 });
  });

  it('the centre maps to the centre', () => {
    expect(worldToMinimap({ x: 3200, y: 3200 }, rect, MAP)).toEqual({ x: 87, y: 87 });
  });

  it.each([
    [0, 0], [MAP, 0], [0, MAP], [MAP, MAP], [3200, 3200], [1234, 5678],
  ])('round-trips (%i, %i) at both rects', (x, y) => {
    for (const r of [rect, { x: 100, y: 60, size: 600 }]) {
      const back = minimapToWorld(worldToMinimap({ x, y }, r, MAP), r, MAP);
      expect(back.x).toBeCloseTo(x, 6);
      expect(back.y).toBeCloseTo(y, 6);
    }
  });

  // The axis-inversion bug a round trip cannot see.
  it('y grows downward, like the world', () => {
    const top = worldToMinimap({ x: 0, y: 0 }, rect, MAP);
    const bottom = worldToMinimap({ x: 0, y: MAP }, rect, MAP);
    expect(bottom.y).toBeGreaterThan(top.y);
  });
});

describe('hitTest', () => {
  it('inside hits, one pixel outside does not', () => {
    expect(hitTest({ x: 13, y: 13 }, rect)).toBe(true);
    expect(hitTest({ x: 161, y: 161 }, rect)).toBe(true);
    expect(hitTest({ x: 11, y: 13 }, rect)).toBe(false);
    expect(hitTest({ x: 13, y: 163 }, rect)).toBe(false);
  });
});
```

- [ ] **Step 2: Run, read the failure**

`npx vitest run tests/game/map/Minimap.test.ts` — expect `TypeError: worldToMinimap is not a function` (Vitest 1.6.1's wording for a missing named export). A failure showing a *conflicting real value* means this plan is wrong; stop.

- [ ] **Step 3: Implement**

Pure module-level functions, no p5, no class yet:

```ts
export interface MinimapRect { x: number; y: number; size: number }
export interface Point { x: number; y: number }

/** Collapsed edge length in screen pixels, and its inset from the corner. */
export const MINIMAP_SIZE = 150;
export const MINIMAP_MARGIN = 12;
/** Expanded edge length, as a fraction of the viewport's shorter side. */
export const EXPANDED_FRACTION = 0.8;

/**
 * One transform, parameterised by the rect: the expanded and collapsed maps
 * differ only in that rect, so the teleport tap and the dot placement cannot
 * disagree with each other.
 */
export const worldToMinimap = (world: Point, rect: MinimapRect, mapSize: number): Point => ({
  x: rect.x + (world.x / mapSize) * rect.size,
  y: rect.y + (world.y / mapSize) * rect.size,
});

export const minimapToWorld = (screen: Point, rect: MinimapRect, mapSize: number): Point => ({
  x: ((screen.x - rect.x) / rect.size) * mapSize,
  y: ((screen.y - rect.y) / rect.size) * mapSize,
});

export const hitTest = (point: Point, rect: MinimapRect): boolean =>
  point.x >= rect.x &&
  point.x <= rect.x + rect.size &&
  point.y >= rect.y &&
  point.y <= rect.y + rect.size;
```

- [ ] **Step 4: Verify** — `npx vitest run tests/game/map/Minimap.test.ts`, then prove falsifiable: invert the `y` in `minimapToWorld` and confirm the axis test and the round trip go red. Revert.

### Task 2: The class, the terrain buffer, and the collapsed draw

**Files:** Modify `src/game/gameObject/map/Minimap.ts`, `src/game/Game.ts`; extend the test.

- [ ] **Step 1: Build it**

`Minimap` holds `expanded = false`, a `rect` getter derived from `expanded` plus the viewport, and two pre-rendered `p5.Graphics` terrain buffers (collapsed and expanded sizes — one scaled to the other is what makes a minimap look muddy).

Build the buffers from `TerrainMap.wallPolygons()` once, and rebuild on `resize(w, h)`. `FogOfWar`'s overlay buffer is the precedent for both the pattern and the resize handling.

`draw()` blits the buffer for the current state, then a border. Called from
`Game.draw()` **after** `this.fogOfWar.draw()` and beside
`this.touchControls.draw()`, and **outside** `camera.makeDraw` — this is screen
space.

The `rect` getter is pure and must be tested headlessly: assert the collapsed
rect is `MINIMAP_MARGIN` from the top-left at `MINIMAP_SIZE`, and that the
expanded rect is `EXPANDED_FRACTION` of the shorter viewport side and centred.

- [ ] **Step 2: Verify** — `npx vitest run tests/game/map/`, `npx vue-tsc --noEmit`, then `npm run dev` and look: terrain visible top-left, no frame-rate change.

- [ ] **Step 3: Commit**

### Task 3: Units, the camera rect, and fog

**Files:** Modify `src/game/gameObject/map/Minimap.ts`

- [ ] **Step 1: Draw the live layer**

Each frame, after the terrain blit:

- The player, in a distinct colour, always.
- Every other unit with `visibleToPlayerTeam` true, coloured by team from the same
  `TEAM_COLORS` / `NEUTRAL_COLORS` the minions use — a colour must mean the same
  thing in both places.
- Turrets and fountains, which are static and always known.
- `Camera.getBoundingBox()` as a rectangle outline. This is the one element that
  answers "where am I looking".

**Dots are a fixed pixel size**, not derived from `stats.size`: a dot is an icon,
not a scale model, and a 165-unit Cho'Gath must not become a blob covering four
other units.

Do not compute visibility — read `visibleToPlayerTeam`.

- [ ] **Step 2: Verify** — `npm run dev`: walk around, confirm enemy dots appear and disappear with fog, and the view rectangle tracks the camera. Then `node tests/e2e/measure-fog.mjs` and compare against its recorded 0.34ms fog draw / ~58fps: the minimap must not cost more than the thing beside it.

- [ ] **Step 3: Commit**

### Task 4: Expand and collapse

**Files:** Modify `src/game/gameObject/map/Minimap.ts`, `src/game/Game.ts`, `src/scenes/GameScene.ts`; extend the test.

- [ ] **Step 1: Route input**

The minimap needs **first refusal** on touches and clicks inside its rect,
before `TouchControls` sees them — otherwise a tap on the minimap also aims a
spell. `TouchControls` has hit-testing to model this on, but the ordering is new
and is the likeliest source of a "minimap works, aiming broke" regression.

Collapsed: a tap inside → `expanded = true`.
Expanded: a tap **outside** the expanded rect → collapse, and that touch must
still reach the controls underneath. There must be a dismiss that is not a
teleport — otherwise opening it by accident forces you to teleport somewhere.

Test headlessly: a routing method that takes a point and the current state and
returns `'expand' | 'collapse' | 'teleport' | 'pass'`. That is the whole
decision, and it should not need a canvas to check.

- [ ] **Step 2: Verify** — `npx vitest run tests/game/map/`, then `node tests/e2e/drive-touch-controls.mjs` and `node tests/e2e/verify-touch-aiming.mjs`. Aiming is what this task can break; `drive-touch-controls` has the one known pre-existing failure and must show no other.

- [ ] **Step 3: Commit**

### Task 5: Teleport

**Files:** Modify `src/game/gameObject/map/Minimap.ts`, `src/game/Game.ts`

- [ ] **Step 1: Wire it**

A tap inside the expanded rect → `minimapToWorld` → `player.teleportTo(x, y)` →
collapse. `teleportTo` already does `markDisplaced()`, `pathAgent.clear()` and
sets both `position` and `destination`; it does not check terrain and does not
need to, because `TerrainMap.update()` pushes a body out of a wall next tick.

Say plainly in the file comment that this makes the minimap a practice tool
rather than a neutral HUD element — a reader who assumes "minimap" means "the
LoL minimap" will expect a move order.

- [ ] **Step 2: Verify** — `npm run dev`: expand, tap a far corner, confirm the champion is there and the map collapsed.

- [ ] **Step 3: Commit**

## Self-review notes

- **Task 1's round-trip test is deliberately paired with absolutes.** A
  transform wrong by the same factor in both directions round-trips perfectly;
  three fixed-point assertions and an axis-direction assertion are what actually
  pin it.
- **Task 4 is the risk**, not Task 5. Teleport is one call to a method that
  already exists; input routing is new ordering in a path two other systems
  already share.
- **Perf is asserted against a recorded baseline** (`measure-fog.mjs`, 0.34ms /
  58fps), not against a feeling.
